# Архитектура и очистка проекта — 10 ноября 2026

Проект — монолитное приложение Python/Kivy с SQLite. После очистки осталось
178 производственных Python-модулей; 172 достижимы от `main.py` через обычные
и обнаруженные динамические импорты. Проверка учитывала также тесты,
инструменты разработки, JSON/atlas, шаблоны путей и строковые значения
рабочей базы и её таблиц `_default`. Рабочая партия при очистке не изменялась.

| Область | Ответственность |
|---|---|
| `main.py`, `game_loading.py`, `release_state.py` | Запуск, меню, создание партии, совместимость Android |
| `game_process.py`, `ii.py`, `ai_strategy.py`, `ai_models/` | Ход кампании, ИИ, дипломатия |
| `economic.py`, `city_construction.py`, `city_development.py`, `utils/market_income.py` | Экономика и единый каталог строительства |
| `fight.py`, `tactical_battle_bridge.py`, `tactical_combat.py` | Общий результат боя, выбор режима и независимая тактическая модель |
| `otherworlds.py`, `mirror_*`, `portal_*`, `monster_*` | Зазеркалье, экспедиции, расследования, монстры |
| `strategy_ui.py`, `responsive_ui.py`, `*_ui.py`, `town_scene.py` | Общие элементы интерфейса и отображение |
| `db_lerdon_connect.py`, миграции рядом с подсистемами | SQLite, запуск миграций и совместимость сохранений |
| `files/` | Игровые изображения, анимации, музыка, звуки, атласы |
| `assets/` | Исходники оформления, промпты, отчёты и предпросмотры; также значок и заставка сборки |
| `tests/`, `tools/` | Проверки, генераторы, упаковка ресурсов и подготовка выпуска |
| `.release/` | Локальное окружение проверок, сборки APK, резервные копии; исключено из APK |

Крупнейшие файлы: `ii.py` — 5073 строки, `game_process.py` — 3842,
`main.py` — 3258, `economic.py` — 2428, `ui.py` — 2271,
`fight.py` — 1982. Они совмещают несколько обязанностей; часть зависимостей
замкнута, а импорты внутри функций откладывают загрузку соседних подсистем.
Поэтому отсутствие верхнеуровневого импорта не означает, что модуль не нужен.

Самые существенные архитектурные риски: соединения с SQLite и инициализация
с побочными эффектами при импорте, обмен одним соединением между интерфейсом
и фоновым ходом, а также смешение правил кампании с её отображением.
Тактическая модель уже отделена от базы; мост боя и охота используют отдельное
соединение рабочего потока. Аналогичное разделение остальных операций стоит
делать отдельными небольшими изменениями с проверками, а не в ходе удаления файлов.

Очистка убрала из рабочих каталогов 404 файла общим размером 58 148 135 байт
(55,45 МиБ):

| Группа | Количество |
|---|---:|
| Устаревшие игровые изображения: прежнее обучение, старые знаки званий, неиспользуемые фоны и портреты | 36 |
| Архивные предшественники из `old/` | 5 |
| Модули без потребителей: `db_manager.py`, `mirror_allegiance_ui.py` | 2 |
| Побайтовый дубликат `buildings-reference-sheet.jpg` (сохранён оригинал в `assets/`) | 1 |
| Старые `buildozer.log` и `debug.log` | 2 |
| Воспроизводимые файлы `__pycache__/*.pyc` | 358 |

Все файлы сначала помещены в проверенный ZIP с исходными относительными путями
и SHA-256. Архив: `.release/unused-files-20261110-162734.zip`.
Полный список и причины удаления: `.release/cleanup-manifest.json`.
Архив занимает около 30,71 МиБ и исключён из APK; экономию места рабочих
каталогов не следует путать с уменьшением всей папки вместе с резервной копией.

Сохранены все 172 достижимых модуля и все 937 ресурсов, для которых обнаружена
ссылка или динамическое семейство путей. Не удалены тесты, генераторы, миграция
`migrate_units_schema.py`, пакет `utils`, публичные компоненты `ai_models/ui`
с потребителями в тестах, промпты и исходники оформления. Документ
`files/map/redrawn/PROMPTS.md` оставлен как источник для перерисовки карт.
Наличие только тестового или инструментального потребителя не считается
достаточным основанием для удаления.

Повторный аудит без удаления:

```powershell
.release/ui-check/Scripts/python.exe tools/audit_project_usage.py --output .release/project-usage-audit.json
```

Это консервативный статический анализ, а не доказательство неиспользования
любого оставшегося файла. Кандидаты `review` требуют ручной проверки, особенно
при конкатенации путей, переборе каталогов и загрузке старых сохранений.
Архив допускает восстановление конкретного файла по его относительному пути;
массовое извлечение поверх новых изменений без проверки не требуется.
