# Lerdon: сервис ЮKassa для REG.RU

Цены: 250 ₽ навсегда; 55 ₽ за календарный месяц с автопродлением.
PHP 8.2+ (на сайте выбран 8.3), MySQL 8, расширения PDO MySQL, cURL, OpenSSL.
Composer, Python, отдельный VPS не нужны.
Расширение Sodium не используется. Шифрование — AES-256-GCM с проверкой
целостности, подпись лицензий — RSA-3072/SHA256 (RS256).

## Что уже реализовано

- Приём одноразового payment_token от Android SDK и создание платежа по API.
- Фиксированные цены на сервере; клиент не может назначить сумму.
- Проверка магазина, режима test/live, валюты, суммы и идентификаторов заказа.
- Уведомления перепроверяются запросом к API ЮKassa, а не по присланному статусу.
- UUID идемпотентности сохраняется до запроса к банку. Таймаут повторяется с тем
  же ключом; после 23 часов неопределённый заказ требует ручной проверки.
- Однократная выдача покупки, отдельный оплаченный срок и согласие на продление.
- Отмена в API и на странице manage.php. Оплаченный период сохраняется.
- Покупка навсегда отключает дальнейшие автоматические продления.
- CRON для обработки незавершённых платежей и ежемесячных списаний.
- Возвраты отзывают доступ, выданный конкретным платежом. Любой частичный возврат
  также отзывает его полностью; частичный доступ/пропорциональная отмена не реализованы.
- Личный код восстановления: секрет 256 бит, в БД хранится только его хеш.
  Код требуется сохранить пользователю. Почта не является способом авторизации;
  отправки кодов по почте и восстановления потерянного кода здесь пока нет.
- Подпись лицензии RSA-3072/SHA256. Приложение должно проверять подпись заранее встроенным
  открытым ключом, а не доверять полю public_key из ответа. TEST-лицензии нельзя
  принимать в боевой версии игры. Клиент проверяет подпись перед сохранением
  лицензии и учитывает срок доступа при офлайн-запуске.

## Подарочные ключи полной версии

В игре: «Полная версия» → «Активировать подарочный ключ». Получатель указывает
почту и ключ. Сервер выдаёт ту же подписанную бессрочную лицензию, что используется
для полной версии. Карта и мобильный SDK для активации ключа не нужны.

Обновление уже работающего сервера:

1. Из нового архива загрузите `Billing.php` и `gifts.php` в `~/lerdon-pay-private/`,
   `schema.sql` туда же, а `api.php` в `~/www/pay.katin-sharic.ru/`.
   Существующий `config.php` и секретные ключи сохраняйте без изменений.
2. В Shell-клиенте выполните `php ~/lerdon-pay-private/setup.php`.
   Добавится таблица ключей; аккаунты и покупки не удаляются.
3. Выпустите, например, пять ключей:

   ```sh
   php ~/lerdon-pay-private/gifts.php create 5 "Подарки игрокам"
   ```

Команда печатает ID и ключ вида `LERDON-XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX`.
Сам ключ показывается только при выпуске: сохраните его и отправьте получателю
личным сообщением. В базе остаётся лишь SHA-256 хэш, а не исходный ключ.
Публичного API выпуска ключей нет, команда работает только в Shell-клиенте.

Список последних 200 ключей со статусами READY/USED/REVOKED:

```sh
php ~/lerdon-pay-private/gifts.php list
```

Отменить ещё не использованный ключ можно по его ID:

```sh
php ~/lerdon-pay-private/gifts.php revoke ID
```

Каждый ключ активируется одним аккаунтом. Повтор того же запроса после обрыва
связи безопасен; другой аккаунт ключ не получит. Личный код восстановления из
игры позволяет вернуть активированный доступ после переустановки. Сохранённая
подписанная лицензия работает офлайн. Активация отключает автопродление подписки.

Ключи выпускаются в текущем режиме `config.php`: TEST или LIVE. Тестовый ключ
не действует в боевом режиме. Ключи не подтверждают платежи и не обращаются к
ЮKassa; они предназначены для выдачи подарочного доступа разработчиком.
Для работы кнопки нужна обновлённая игра и обновлённый сервер, одна загрузка
серверного архива старое приложение не меняет.

## Граница готовности

Это серверный комплект. Клиентская интеграция SDK, личного кода, проверки
лицензии и ограничений полной версии реализована в проекте. Для новых функций
требуется соответствующая пересборка APK. Одна загрузка архива на хостинг
не обновляет установленную игру. Локальные тесты используют подставной API и
SQLite; MySQL и подключение ЮKassa проверяются отдельно на хостинге.

## 1. Загрузка файлов

В архиве находятся две папки, которые надо распаковать **в домашнюю папку
пользователя хостинга**, на одном уровне с существующей папкой `www`:

```
домашняя_папка/
  lerdon-pay-private/
    Billing.php
    Crypto.php
    bootstrap.php
    config.example.php
    setup.php
    cron.php
    receipts.php
    schema.sql
  www/
    pay.katin-sharic.ru/
      .htaccess
      index.php
      api.php
      manage.php
```

Не загружать закрытую папку внутрь сайта! Не менять файлы katin-sharic.ru.
Не удалять другие файлы из www. Если REG.RU создал в папке поддомена index.html,
сначала переименуйте только эту заглушку, например в index.html.disabled.
Для сайта включите перенаправление HTTP → HTTPS. Публичная директория должна
указывать именно на www/pay.katin-sharic.ru (без дополнительного public).
Перенаправление включается в панели REG.RU, не в .htaccess: за HTTPS-прокси
проверка Apache %{HTTPS} может создавать бесконечный редирект.

## 2. Создание закрытой конфигурации

Если уже загружали предыдущий архив, распакуйте новый на том же уровне с заменой
файлов сервиса. config.php в архиве отсутствует и не должен удаляться.
В вашей предыдущей попытке setup.php остановился на отсутствии Sodium ещё до
создания ключей и таблиц, поэтому миграция данных не требуется.
Если конфигурация со старыми Sodium-ключами всё же была создана, не удаляйте её
и не генерируйте ключи заново: потребуется отдельная миграция. Эта версия
отказывается читать старые ключи и шифротексты вместо их тихой замены.

В «Shell-клиенте» перейдите в домашнюю папку. Проверьте `php -v`: нужна версия 8.2+.
Выбранная версия сайта не обязательно совпадает с версией CLI. Если CLI старее,
уточните у REG.RU путь к исполняемому PHP 8.3 и используйте его вместо `php`.

```
php lerdon-pay-private/setup.php --check
php lerdon-pay-private/setup.php
```

Команды выполняйте по одной строке. --check проверяет PHP, openssl, pdo_mysql,
curl, AES-256-GCM и RSA/SHA256. Он не создаёт конфигурацию, не подключается к БД
и не делает платежей. Если все строки начинаются с OK, запускайте вторую команду.

Первый запуск создаст config.php со случайными ключами. Через менеджер файлов
отредактируйте **только закрытый** lerdon-pay-private/config.php:

- dsn уже содержит БД u3605097_lerdon_pay и 127.0.0.1:3306;
- db_user — реальный пользователь этой БД;
- db_password — его пароль;
- shop_id — идентификатор тестового магазина ЮKassa;
- api_secret — секретный API-ключ этого тестового магазина;
- test_mode=true, live_enabled=false оставьте на время тестов;
- recurring_enabled включайте только после подтверждения поддержки автоплатежей.

Не заменяйте сгенерированные app_key и signing_secret. Сделайте их закрытую
резервную копию вместе с базой: потеря ключей нарушит работу существующих покупок.
Ключ клиентского SDK и секретный API-ключ магазина — разные ключи.
Секретный API-ключ, пароль БД и config.php не отправляйте в чат и не кладите в APK.

Повторите ту же команду setup.php. Она создаст таблицы и выведет только открытый
ключ подписи для будущей сборки игры. Повторный запуск не очищает покупки.

## 3. Настройки ЮKassa

Настройте адрес HTTP-уведомлений:

https://pay.katin-sharic.ru/api.php?action=webhook

События: payment.succeeded, payment.canceled, refund.succeeded.
capture=true: отдельное ручное подтверждение платежа не нужно.
Страница управления подпиской: https://pay.katin-sharic.ru/manage.php

У менеджера отдельно подтвердите:
1. разрешены платежи одноразовым токеном мобильного SDK;
2. разрешены автоплатежи для вашего магазина и статуса самозанятого;
3. какие способы оплаты поддерживают сохранение платёжного средства.

«Магазин подключён» само по себе не подтверждает все три пункта.

## 4. CRON

В «Планировщик CRON» добавьте выполнение каждые 5 минут:

```
php /ПОЛНЫЙ_ПУТЬ_К_ДОМАШНЕЙ_ПАПКЕ/lerdon-pay-private/cron.php
```

Укажите тот же PHP 8.3, что использовали для setup.php. Полный путь можно узнать
через `pwd` в домашней папке. Нельзя запускать cron.php по HTTP.
Неизвестный результат платежа не следует вручную заменять новым заказом:
проверьте его в кабинете ЮKassa. Заказы в статусе review блокируют новые покупки
аккаунта до ручного разбора; автоматической админ-панели здесь нет.

## 5. Чеки самозанятого

ЮKassa подтверждает платёж, но этот комплект **не регистрирует доход в «Мой налог»**.
Нужно организовать формирование и отправку чеков по каждой оплате, включая
продления. После возврата потребуется корректировка/аннулирование чека.
Вариант первого запуска — ручная обработка очереди:

```
php lerdon-pay-private/receipts.php
php lerdon-pay-private/receipts.php mark-issued ID_ЗАКАЗА
```

Первая команда выводит CSV с почтой, суммой и идентификатором платежа; не
сохраняйте его в публичной папке. Вторая только отмечает, что чек уже выдан,
сама чек не создаёт. Записи с возвратами включены для ручной проверки.
Для больших продаж/подписок понадобится автоматизация чеков через совместимого
партнёра НПД. Только когда процесс выдачи чеков действительно организован,
установите npd_receipts_ready=true.

## 6. Проверка и переход в live

Проверьте на хостинге https://pay.katin-sharic.ru/api.php?action=catalog:
ответ должен быть JSON с 5500 и 25000 копейками и test=true.
Полную проверку оплаты проводим после подключения Android SDK к игре:
успех, отказ, возврат, двойной клик, восстановление кода, отмена и продление.

Для live используйте отдельную пустую БД и отдельные ключи подписи/шифрования,
чтобы тестовые аккаунты и покупки не переносились в настоящие.
Настройте настоящие shop_id/api_secret, test_mode=false, live_enabled=true,
npd_receipts_ready=true. recurring_enabled=true только после отдельного
согласования и проверки условий/кнопки отмены. Сохраняйте резервные копии.

До запуска нужны фактические сведения о продавце, условия приобретения и
подписки, возвратов и обработки данных. В этом комплекте юридическая оферта
не выдумана и не опубликована; включение боевого режима выполняется отдельно.

## API для Android

### Переход с тестового магазина на настоящий (55 ₽ / 250 ₽)

Обновите `Billing.php` в `~/lerdon-pay-private/` и `index.php` в
`~/www/pay.katin-sharic.ru/`. Новый каталог возвращает 5500 и 25000 копеек.
Обновляйте приложение вместе с сервером: старая версия с другими ценами
заблокирует новую покупку при несовпадении каталога.

Для настоящего магазина создайте отдельную пустую MySQL-базу. Сохраните
тестовый `config.php` вне публичной папки, затем подготовьте новый `config.php`
через `setup.php`: будут созданы новые ключи подписи и шифрования. Заполните
доступ к новой базе, `shop_id` настоящего магазина и его `api_secret`.
Секрет API вводится только на сервере, в приложение он не передаётся.
Укажите `test_mode=false`, `live_enabled=true`, `npd_receipts_ready=true`
после настройки выдачи чеков. `recurring_enabled` включайте после подключения
автоплатежей ЮKassa; до этого доступна только покупка навсегда.

Повторите `php ~/lerdon-pay-private/setup.php`. Для сборки приложения нужны
shopId настоящего магазина, его ключ **мобильного SDK** и новый открытый ключ,
который напечатает setup.php. В `billing_config.json` используются эти значения
и `test_mode=false`. Тестовый SDK-ключ для настоящего магазина не подходит.
На настоящем магазине настройте те же HTTP-уведомления:
`https://pay.katin-sharic.ru/api.php?action=webhook`.

Не переносите тестовые аккаунты, заказы и подарочные ключи в боевую базу.
Локальная партия игры при смене магазина сохраняется; TEST-лицензия не
открывает боевую версию. Серверный CRON должен использовать новый `config.php`.

Без авторизации:
- GET api.php?action=catalog
- POST api.php?action=register, JSON {"email":"..."}; выдаёт личный recovery_code.
- POST api.php?action=webhook — только для событий ЮKassa.

С `Authorization: Bearer ЛИЧНЫЙ_КОД`:
- POST api.php?action=create: plan, request_id (16–64 латинских знака, новый
  для новой покупки), payment_token из SDK, recurring_consent=true для подписки.
  При повторе одного запроса используйте прежний request_id, не новый.
- GET api.php?action=order&id=ID_ЗАКАЗА — обновление по API ЮKassa.
- GET api.php?action=entitlement — лицензия с подписью.
- POST api.php?action=cancel с JSON {} — отключить продление.

confirmation_url из create/order надо передавать Android SDK для подтверждения
платежа. Ни URL возврата, ни сообщение SDK не являются доказательством оплаты.
Личный код не передаётся в URL. Публичный доступ к MySQL не нужен.
Формат лицензии v2: algorithm=RS256; подпись вычисляется над ASCII-строкой
signed_payload (не над декодированным JSON). public_key — base64 от публичного
PEM SubjectPublicKeyInfo. Приложение фиксирует RS256 и доверенный ключ в своей
сборке; не выбирает алгоритм или доверенный ключ по ответу сервера.
